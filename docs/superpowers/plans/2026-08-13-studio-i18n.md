# Seller Studio i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Seller Studio's entire UI follow the language selector, so all buttons, labels, tabs, hints, statuses, and error messages switch between English and Chinese (or any locale the seller has configured).

**Architecture:** A React Context provider (`StudioI18nProvider`) at the app root, with a `useStudioT()` hook returning `t(key, params?)`. The dictionary is built-in (template-owned, `studio/src/i18n/`) with optional seller overrides via `content/config.ts`. Merge order: built-in EN → built-in locale → seller override.

**Tech Stack:** React Context + hooks, TypeScript, Vitest + @testing-library/react, Vite SPA (Seller Studio)

## Global Constraints

- New config fields in `SiteConfig` must be `?`-optional and read with `?? default` (Iron Rule 8)
- `content/` folder is seller-owned — never write template code there (Iron Rule 1)
- Bilingual docs: every English doc update has a `_zh.md` counterpart (Iron Rule 2)
- `pnpm studio` is local-only by design, binds 127.0.0.1
- Tests use vitest + @testing-library/react; existing tests should not break from string changes
- The built-in English dictionary must produce the *exact same* strings as the current hardcoded ones, so existing component tests' text assertions pass unchanged
- `{plural}` token in English templates expands to `"s"` when count !== 1, `""` when count === 1. Other locale templates override the whole string and ignore `{plural}`
- `scripts/lib/siteReadiness.ts` is shared with `pnpm doctor` — changes must be additive only

- [ ] **Step 4: Create `resolve.ts`**

```ts
// studio/src/i18n/resolve.ts
import type { StudioStrings } from "./types";
import { EN } from "./strings.en";
import { ZH } from "./strings.zh";

const BUILTIN: Record<string, Partial<StudioStrings>> = {
  zh: ZH,
};

export function resolveStudioStrings(
  locale: string,
  overrides: Record<string, Record<string, string>>,
): StudioStrings {
  return {
    ...EN,
    ...(BUILTIN[locale] ?? {}),
    ...(overrides[locale] ?? {}),
  } as StudioStrings;
}

export function format(
  template: string,
  params?: Record<string, string | number>,
): string {
  if (!params) return template;
  let result = template;
  for (const [key, value] of Object.entries(params)) {
    result = result.replaceAll(`{${key}}`, String(value));
  }
  // English pluralization: {plural} → "s" when count !== 1
  if (params.count !== undefined) {
    result = result.replace("{plural}", params.count === 1 ? "" : "s");
  }
  return result;
}
```

- [ ] **Step 5: Create `StudioI18n.tsx`**

```tsx
// studio/src/i18n/StudioI18n.tsx
"use client";

import { createContext, useContext, useMemo } from "react";
import type { StudioKey, StudioI18nValue } from "./types";
import { resolveStudioStrings, format } from "./resolve";

const StudioI18nContext = createContext<StudioI18nValue | null>(null);

export function StudioI18nProvider({
  locale,
  overrides = {},
  children,
}: {
  locale: string;
  overrides?: Record<string, Record<string, string>>;
  children: React.ReactNode;
}) {
  const value = useMemo<StudioI18nValue>(() => {
    const dict = resolveStudioStrings(locale, overrides);
    return {
      locale,
      t: (key: StudioKey, params?: Record<string, string | number>) =>
        format(dict[key] ?? key, params),
    };
  }, [locale, overrides]);

  return (
    <StudioI18nContext.Provider value={value}>
      {children}
    </StudioI18nContext.Provider>
  );
}

export function useStudioT(): StudioI18nValue {
  const ctx = useContext(StudioI18nContext);
  if (!ctx) throw new Error("useStudioT must be used within StudioI18nProvider");
  return ctx;
}
```
